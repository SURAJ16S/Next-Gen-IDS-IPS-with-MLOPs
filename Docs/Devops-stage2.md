# Phase 2: Security Validation & Malware Auditing Workflow

> **Integration Context:** This document dictates the immediate post-generation phase of the DevOps pipeline. Before the synthesized application is containerized and tested in the gVisor sandbox, it must pass a rigorous, multi-layered security gauntlet utilizing open-source semantic analysis and malware detection.
> **Environment:** 100% Local (Zero-Cost Proof of Concept)
> **Target Directory additions:** `DevOps/scripts/02-security-gate.sh`

---

## 1. Semantic Static Application Security Testing (SAST)

[cite_start]Standard regular-expression scanners are often too brittle and generate excessive false positives[cite: 7]. Instead, this pipeline analyzes the fundamental logic of the generated code.

**The Workflow:**
1. [cite_start]**AST Parsing:** The local source code generated in Phase 1 is parsed into Abstract Syntax Trees (ASTs)[cite: 7, 8, 9]. 
2. [cite_start]**Semantic Querying:** The system identifies deep semantic vulnerabilities regardless of how the AI formatted the code, named its variables, or structured its line breaks[cite: 7, 9].

**Zero-Cost Implementation:**
* [cite_start]**Tooling:** **Semgrep Community Edition**[cite: 10]. [cite_start]Licensed under LGPL v2.1, it serves as the open-source program analysis engine at the heart of the platform[cite: 10].
* **Execution:** Run locally against the staging directory. 
  * *Command:* `semgrep scan --config auto /tmp/devops-build/`

---

## 2. Supply Chain Validation and Reachability Analysis

[cite_start]Because AI-generated code can inadvertently hallucinate vulnerable dependency chains or utilize deprecated third-party libraries, the pipeline must validate the supply chain[cite: 7].

**The Workflow:**
1. **Dependency Mapping:** The pipeline evaluates third-party dependencies defined in the project manifests (e.g., `package.json`, `requirements.txt`).
2. **Reachability Analysis:** The system traces the execution path. [cite_start]If a vulnerable function within a third-party library is never actually called by the proprietary code, the vulnerability is flagged as unreachable, reducing false positives[cite: 7].

**Zero-Cost Implementation:**
* **Tooling:** Semgrep Community Edition (for AST trace) paired with open-source OSV-Scanner (for manifest checking).
* **Execution:** * *Command:* `osv-scanner -r /tmp/devops-build/`

---

## 3. Malware and Artifact Scanning

[cite_start]While Semgrep provides exhaustive static analysis, traditional artifact scanning must be executed to ensure no malicious payloads were introduced during the build process[cite: 12, 13].

**The Workflow:**
1. [cite_start]**Archive Unpacking:** The scanner automatically unpacks various file and archive formats generated by the build[cite: 12, 13].
2. [cite_start]**Signature Matching:** The compiled binaries, application artifacts, and configuration files are evaluated against continuously updated signature databases for known trojans, viruses, adware, and ransomware[cite: 12, 13].

**Zero-Cost Implementation:**
* [cite_start]**Tooling:** **ClamAV**, the open-source standard for malware detection[cite: 12, 13].
* **Execution:** Operating as a multi-threaded background scanner daemon on the local developer machine.
  * *Command:* `clamscan --recursive --infected /tmp/devops-build/`

---

## 4. Dynamic Application Security Testing (DAST) Correlation

[cite_start]While this step technically executes *during* the Phase 3 Ephemeral Sandbox, the configuration and correlation rules are defined here in Phase 2. Static analysis cannot be fully trusted until the code is executed under real-world conditions[cite: 11].

**The Workflow:**
1. [cite_start]**Fuzzing:** A dynamic testing engine interacts with the running application inside the sandbox, fuzzing API endpoints and assessing runtime behavior[cite: 11].
2. [cite_start]**Correlation:** The system automatically correlates the dynamic runtime findings directly with the static AST issues found by Semgrep[cite: 11]. [cite_start]This allows developers to see exactly where a theoretical vulnerability is actively exploitable[cite: 11].

**Zero-Cost Implementation:**
* **Tooling:** **StackHawk Developer Tier** (Free) or OWASP ZAP (100% open-source alternative).
* **Execution:** Triggered via a local script hitting the Minikube endpoint.
  * *Command:* `hawkscan make stackhawk.yml`

## 5. Next Steps for Implementation

To operationalize this phase locally without cost, the DevOps team must ensure the following script exists and stops the pipeline (Exit Code 1) if Critical or High vulnerabilities are detected:

1. **Create the Script:** `DevOps/scripts/02-security-gate.sh`
2. **Logic Flow:**
   ```bash
   #!/bin/bash
   echo "Starting Phase 2: Security Validation..."
   
   echo "Running Semgrep CE (SAST)..."
